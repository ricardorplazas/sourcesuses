# How much detail belongs in an interview LBO

**Intent:** allocate modelling effort according to decision impact. **Reviewed:** 16 July 2026.

An interview model is complete when it answers the requested investment questions reliably—not when it reproduces every schedule that could exist in a live transaction model.

## Build the decision spine first

1. Transaction assumptions and sources & uses
2. Operating case and cash conversion
3. Debt schedule and interest
4. Exit bridge and sponsor returns
5. Base/downside comparison
6. Visible integrity checks

## Add detail when it changes the answer

Create segment, geography, cohort or branch schedules only when the case provides enough evidence and the schedule materially explains growth, margins, cash flow or downside. Detail added for appearance creates more formula risk and consumes communication time.

## Simplify transparently

When instructions permit assumptions, state them. Examples include interest timing, tax approximation, fee amortisation and exit-date convention. A transparent simplification is easier to evaluate than unexplained false precision.

## Omit carefully

Do not build unsupported complexity such as circular debt structures, detailed tax attributes or acquisition modules unless requested or necessary. But never omit core cash items merely because they are inconvenient.

## Stop rule

Stop expanding the model when the next schedule is less likely to change the decision than checking the existing model or improving the recommendation.

This prioritisation framework is original educational guidance, not a universal recruiting rule.
